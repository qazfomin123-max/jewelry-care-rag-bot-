# Jewelry Care RAG Bot

Telegram-бот-консультант по уходу за ювелирными изделиями. Отвечает на
вопросы о золоте, серебре, бриллиантах, пробах металлов и размерах колец
на основе базы знаний из статей на русском языке — используя RAG
(Retrieval-Augmented Generation), а не общие знания языковой модели.

Бот не выдумывает ответы: он находит релевантные фрагменты базы знаний
и передаёт их языковой модели как контекст. Если вопрос выходит за
пределы базы — бот честно об этом говорит.

## Как это работает

1. Статьи из `knowledge_base/` разбиваются на смысловые блоки (чанки) с
   перекрытием, чтобы не терять контекст на границах абзацев.
2. Каждый блок превращается в вектор (эмбеддинг) моделью
   `intfloat/multilingual-e5-small` и сохраняется в ChromaDB.
3. На вопрос пользователя строится такой же вектор, ищутся ближайшие
   блоки по косинусному расстоянию, нерелевантные (слишком далёкие)
   отсеиваются по порогу.
4. Найденные фрагменты передаются Claude как контекст — модель отвечает
   на их основе, живым языком, без markdown-разметки (для чистого вида
   в Telegram).

## Стек

- **Python 3.11**
- **ChromaDB** — векторное хранилище
- **sentence-transformers** (`intfloat/multilingual-e5-small`) — эмбеддинги
- **Claude API** — генерация ответа
- **python-telegram-bot** — интерфейс бота
- **GitHub Actions** — автоматическая пересборка индекса

## Структура проекта

```
.
├── main.py                       # запуск Telegram-бота
├── rag_core.py                   # поиск, сборка промпта, запрос к Claude
├── build_index.py                # построение векторного индекса из knowledge_base/
├── knowledge_base/                # статьи с базой знаний (.txt)
├── chroma_db/                     # векторная база (пересобирается автоматически, см. ниже)
├── .github/workflows/
│   └── build-index.yml           # автопересборка индекса при изменении базы знаний
├── requirements.txt
└── .env.example
```

## Установка и запуск

1. Клонируй репозиторий и перейди в его папку:
   ```bash
   git clone https://github.com/qazfomin123-max/jewelry-care-rag-bot-.git
   cd jewelry-care-rag-bot
   ```

2. Создай виртуальное окружение и установи зависимости:
   ```bash
   python -m venv venv
   venv\Scripts\activate        # Windows
   pip install -r requirements.txt
   ```

3. Скопируй `.env.example` в `.env` и заполни своими значениями:
   ```
   TOOKEN_API_KEY=...
   TELEGRAM_BOT_TOKEN=...
   RAG_TOP_K=6
   RAG_MAX_DISTANCE=0.163
   ```

4. Собери индекс (если `chroma_db/` ещё не подтянулась из репозитория
   или база знаний изменилась локально):
   ```bash
   python build_index.py
   ```

5. Запусти бота:
   ```bash
   python main.py
   ```

## Автосборка индекса

При любом изменении файлов в `knowledge_base/`, `build_index.py` или
`requirements.txt` GitHub Actions автоматически пересобирает `chroma_db/`
и коммитит её обратно в репозиторий. Это значит, что хостингу, на
котором крутится бот, достаточно склонировать репозиторий — не нужно
прогонять модель эмбеддингов на каждом старте.

Запустить пересборку вручную: вкладка **Actions** → **Build RAG Index**
→ **Run workflow**.

## Калибровка порога релевантности

`RAG_MAX_DISTANCE` подобран не на глаз, а по замерам: прогнан набор
контрольных вопросов (по теме базы и заведомо не по теме), найдена
граница между настоящими совпадениями и шумом. Скрипт для повторной
калибровки — `debug_distances.py`; стоит перезапускать его при смене
модели эмбеддингов или существенном расширении базы знаний.

## Известные ограничения

Порог релевантности откалиброван на текущий состав базы знаний (пять
основных тем). Вопросы, лексически близкие к теме украшений, но по
факту не входящие в базу (например, про ремонт часов), могут изредка
проходить порог — граница между «похоже» и «непохоже» у модели такого
размера не идеальна.
