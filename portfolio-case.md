# RAG-бот для консультаций по уходу за ювелирными изделиями

Telegram-бот, который отвечает на вопросы о золоте, серебре, бриллиантах,
пробах и размерах колец — на основе базы знаний из 20+ статей на русском
языке. Построен на RAG (Retrieval-Augmented Generation): бот не выдумывает
ответы, а находит релевантные фрагменты базы и передаёт их языковой модели
как контекст.

## Задача

Нужен был консультант, который отвечает живым языком, но строго по
фактам из конкретной базы знаний, а не общими фразами вида "ухаживайте
бережно". И явно говорит "не знаю", если вопрос выходит за пределы базы,
а не выдумывает правдоподобный, но неверный ответ.

## Как устроено

- **Хранение и поиск** — ChromaDB, векторная база данных
- **Эмбеддинги** — `intfloat/multilingual-e5-small`, мультиязычная модель
  для семантического поиска на русском тексте
- **Генерация ответа** — Claude, через API
- **Интерфейс** — Telegram-бот (`python-telegram-bot`, polling)
- **CI/CD** — GitHub Actions пересобирает векторную базу автоматически при
  любом изменении базы знаний, коммитит готовый индекс обратно в
  репозиторий — хостингу не нужно гонять модель эмбеддингов при каждом
  старте

## Технически интересная часть: почему бот путал золото и серебро

На раннем этапе бот стабильно подмешивал фрагменты про уход за золотом
в ответы про серебро — даже когда вопрос был явно про серебро. Не баг в
привычном смысле: код исполнялся без ошибок, просто результаты поиска
были нерелевантны.

Диагностика через прямой вывод расстояний между запросом и найденными
фрагментами показала: причина — в том, как эмбеддинг-модель семейства E5
ожидает вход. Такие модели обучены с обязательными префиксами (`query: `
для вопросов, `passage: ` для текста базы) — без них модель хуже разводит
семантически близкие, но разные темы. После добавления префиксов и
пересборки индекса нужный источник стал уверенно занимать первое место
в выдаче по релевантным запросам.

Дальше — откалибровал порог отсечения нерелевантных результатов
(`RAG_MAX_DISTANCE`) не на глаз, а по реальным замерам: прогнал набор
контрольных вопросов (по теме и заведомо не по теме) и нашёл границу,
где заканчиваются настоящие совпадения и начинается шум.

## Результат

Бот отвечает на вопросы по теме конкретно и по делу, честно признаёт,
когда вопрос выходит за пределы базы знаний, и обновляет свою базу
автоматически при добавлении новых статей — без ручной пересборки.
